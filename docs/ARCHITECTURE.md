# ARCHITECTURE

> Hand-written reference. Phase 3 (`documentation/engine`) will regenerate this from
> the knowledge base; until then this file and `control/manifest.json` are the
> authoritative description, and `genesis docs`-style output is planned.

## 0 · North star and central rule

*No future session should have to re-read the universe: the project explains,
recovers, continues and improves itself.*

**Central rule:** *Nothing happens without leaving an observable project event.*

## 1 · Five data levels (DEC-00001)

| Level | Path | Purpose | Mutability |
| --- | --- | --- | --- |
| 1 RAW | `data/raw` | everything exactly as it happened | append-only, never interpreted |
| 2 PROCESSED | `data/processed` | rule/AI analysis into typed entities | regenerable |
| 3 KNOWLEDGE | `knowledge/` + `data/indexes/genesis.db` | reusable concepts, traces, graph | regenerable from 1+2 |
| 4 PROJECT | repo root | the real software | patched, never rewritten (POL-0002) |
| 5 CONTROL | `control/` | manifest, state, roadmap, tasks, checkpoints, policies | versioned JSON |

## 2 · Eleven build layers

`0 vision · 1 requirements · 2 architecture · 3 infrastructure · 4 core-engine ·
5 application · 6 agents · 7 automation · 8 verification · 9 documentation ·
10 learning-evolution`

Work proceeds in order; no arbitrary jumps (POL-0010).

## 3 · The pipeline

```
Chat → Capture → Normalization → Analysis → KnowledgeGraph → Documentation
     → Application → Agent → Execution → Verification → Learning
```

Executable today up to **KnowledgeGraph** plus the **Context Engine**:
`genesis capture · process · search · graph · resume`.

## 4 · Decision Traces instead of private reasoning (DEC-00003)

Every decision stores: objective (es/en/pt), context, constraints, alternatives
with rejection reasons, decision, justification, consequence, status. The
provenance chain links it to the searches and sources that informed it. 12 real
traces live in `control/decisions.json` and in the `decisions` table.

## 5 · Interruptions are first-class (DEC-00004)

11 types (`blocked, failed, interrupted, waiting_user, dependency_missing,
tool_error, ambiguity, conflict, resource_limit, security_stop, scope_change`)
and 8 recovery capabilities (`checkpoint, rollback, resume, retry, recover, skip,
pause, continue`; the first four implemented). Real stored example: `INT-00001 ·
security_stop` (GitHub token cannot create repositories) blocking `TSK-00011`.

## 6 · Mutation protocol (POL-0002)

`READ → UNDERSTAND → DIFF → PLAN → PATCH → VERIFY → COMMIT`, with a checkpoint
before and a diff before restoring. Anti-goal: letting any AI rewrite whole files.

## 7 · Application seam (DEC-00005)

One HTTP contract (31 routes, `node:http`, zero dependencies) serves three
consumers: the offline PWA console (`apps/console`), the optional Next.js app
(`apps/web`), and any external adapter (MCP, LangGraph, n8n…) — adapters only,
never core imports (POL-0001).

## 8 · Offline strategy (DEC-00012, POL-0011)

Console = installable PWA. Data order: **live API → service-worker cache →
bundled snapshot.json**. The UI always flags the active mode and the sync time.
Icons are generated by a dependency-free PNG encoder (`scripts/generate-icons.js`).

## 9 · Learning loop (section 24)

`ERROR → ANALYSIS → RECOVERY → LESSON → RULE CREATED → PRECHECK NEXT TIME`.
Two real lessons already exist, each paired with a proposed hard rule.
